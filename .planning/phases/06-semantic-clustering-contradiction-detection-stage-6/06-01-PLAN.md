# Phase 6 Plan — Semantic Clustering + Contradiction Detection (Stage 6)

Requirements: CLUSTER-01, CLUSTER-02, CLUSTER-03. README §8 Stage 6 / §15 Phase 6.
**Tech fixed by the spec: HDBSCAN or BERTopic, over SPECTER2 embeddings, plus
DeBERTa-MNLI for pairwise contradiction detection.**

## Starting position

`app/clustering/` holds only `__init__.py`. Phase 5 is complete and frozen:
`EvidenceIndex.gap_points()` already returns every `limitation` / `future_work`
point with its stored 768-d SPECTER2 vector and full payload. That is this
phase's input and it needs no change.

`app/api/routes_backend.py` survived the incomplete upstream push and is the
**frozen consumer contract** for this phase. It is not rewritten here.

## Contracts pinned by surviving code (must not change)

From `routes_backend.py` (`GET /clusters`, `POST /clusters`, `POST /pipeline/run`)
and `frontend/src/types.ts`:

- `app.clustering.storage.list_clusters(session)` → rows exposing `.id: int`,
  `.label: str | None`, `.member_count: int`, `.contradiction_flag: bool`,
  `.contradiction_score: float`.
- `app.clustering.storage.members_for_cluster(session, cluster_id)` → rows
  exposing `.point_id`, `.paper_id`, `.text`, `.year`.
- `app.clustering.service.rebuild_clusters(session)` **and**
  `rebuild_clusters(session, settings=settings)` → `list[int]` of cluster ids.
  The caller owns the transaction: it calls `session.commit()` afterwards, so
  this function must flush but never commit.
- Phase 7/8 read `cluster_id` against these ids, so ids must be real primary
  keys, not positional labels.

## Decisions

### D-06-01 — HDBSCAN via `sklearn.cluster.HDBSCAN`

README §7/§15 name the *algorithm* ("HDBSCAN or BERTopic"), not a package.
scikit-learn ≥1.3 ships HDBSCAN in-tree (the upstream `hdbscan` implementation,
ported and maintained by the same lineage), so this is HDBSCAN proper.

Chosen over the standalone `hdbscan` package because that package needs a
Cython/C++ build and lags NumPy 2 wheel availability on Windows — a build-time
failure mode this project's environment does not need. scikit-learn is already
resolved into the tree transitively (via `sentence-transformers`), and is added
to `pyproject.toml` explicitly because Phase 6 imports it directly.

Chosen over BERTopic because BERTopic is a pipeline wrapper (UMAP + HDBSCAN +
c-TF-IDF + its own embedding backend) that would want to own the embedding step
SPECTER2 already owns, and pulls `umap-learn`/`numba` — a large dependency
addition for a component whose clustering core is the HDBSCAN we would run
anyway. CLAUDE.md hard constraint 8 (no scope creep) settles it.

This closes the "Phase 6 clustering library" question PROGRESS.md left open
after the project-state reconciliation. The lost upstream build's bare
scikit-learn is *not* being inherited as-is: what it lacked was HDBSCAN, and
`sklearn.cluster.HDBSCAN` supplies exactly that.

### D-06-02 — cosine similarity via L2-normalized vectors + euclidean

Qdrant scores this collection with cosine distance (Phase 5), so clustering
must agree with retrieval. `sklearn.cluster.HDBSCAN` with `metric="cosine"`
forces `algorithm="brute"` and is not supported by its tree backends. On
L2-normalized vectors, `euclidean² = 2 − 2·cosine`, a strictly monotone
transform — so euclidean HDBSCAN over normalized vectors produces exactly the
cosine neighbourhood ordering, with no metric-support caveats. Normalization
happens in this module; the stored vectors are untouched.

### D-06-03 — `microsoft/deberta-base-mnli` is the NLI checkpoint

README fixes "DeBERTa-MNLI". `microsoft/deberta-base-mnli` is the official
DeBERTa MNLI release at ~139M parameters; `deberta-large-mnli` is ~400M for the
same three-way label set. README §13.6 resource safety prefers the smaller
representative model, and the checkpoint is configurable
(`NLI_MODEL`) so the large variant is a `.env` change, not a code change.

**Label indices are read from `model.config.label2id`, never hardcoded.**
DeBERTa MNLI checkpoints do not agree on label order between releases; a
hardcoded index would silently invert entailment and contradiction.

### D-06-04 — only cross-paper pairs are tested for contradiction

CLUSTER-02 and README §8 Stage 6 both describe the signal as *"one paper claims
a method works where another says it fails"* — a disagreement **between**
papers. Two sentences from the same paper contradicting each other is an
extraction artefact, not gap evidence, so same-paper pairs are skipped. This
also removes the dominant source of spurious pairs in a cluster where one paper
contributed several statements.

### D-06-05 — NLI is run in both directions and the pair work is capped

NLI is asymmetric: `P(contradiction | a→b)` ≠ `P(contradiction | b→a)`. Both
orders are scored and the maximum is taken, so a contradiction is not missed
because of statement order.

Pairwise work is O(n²) in cluster size, and it is a transformer forward pass
each — exactly the runaway cost README §13.6 warns about. Candidate pairs per
cluster are therefore capped (`NLI_MAX_PAIRS_PER_CLUSTER`) after a deterministic
ordering, so a 200-member cluster cannot stall a corpus run.

### D-06-06 — cluster labels are derived deterministically, no extra model

`Cluster.label` is `str | None` in the surviving contract and the frontend falls
back to `Cluster {id}` when it is null. A label is a display affordance, not
evidence, so it is produced by frequency-ranked term selection over the member
statements (stopword-filtered, document-frequency weighted) rather than by
adding a topic model or an LLM call. CLAUDE.md hard constraint 6 — the LLM comes
last — forbids the latter here anyway.

### D-06-07 — noise points are not clusters

HDBSCAN assigns `-1` to points it cannot place. They are dropped rather than
swept into a catch-all cluster: a "cluster" of unrelated leftovers would get a
mention count, a trend slope and a gap score in Phases 7–8, manufacturing a gap
out of noise.

## Tasks (TDD — failing test first for each)

1. **Hand-labelled fixture** (`tests/clustering/labelled.py`) — 12
   limitation/future-work sentences across 3 known themes (multilingual /
   English bias, hallucination & factuality, compute cost), plus a
   contradicting cross-paper pair. This is the concrete expected outcome the
   ROADMAP requires established *before* clustering code exists.
2. **`app/clustering/schema.py`** — `GapStatement` (from a `gap_points()` dict),
   `StatementCluster`, `ContradictionPair`; validation at the boundary, since
   payloads originate in PDF text.
3. **`app/clustering/cluster.py`** — `normalize_vectors`, `cluster_statements`
   (HDBSCAN, no fixed cluster count), `label_for_statements`. Deterministic
   ordering of clusters and members.
4. **`app/clustering/nli.py`** — `ContradictionDetector` (injected predict fn,
   bidirectional, batched, capped), `candidate_pairs`, `load_deberta_mnli`
   (lazy heavy imports), `get_detector()` cached per process.
5. **`app/clustering/storage.py`** — `Cluster`, `ClusterMember`,
   `ClusterContradiction` ORM rows; `replace_clusters`, `list_clusters`,
   `members_for_cluster`, `contradictions_for_cluster`.
6. **`app/clustering/service.py`** — `rebuild_clusters(session, settings=None,
   index=None, detector=None)`. No gap points ⇒ `[]` with no model load.
7. **Settings** — `clustering_min_cluster_size`, `clustering_min_samples`,
   `clustering_max_statements`, `nli_model`, `nli_model_revision`,
   `nli_batch_size`, `nli_max_chars`, `nli_max_pairs_per_cluster`,
   `contradiction_threshold`. Bounded on both ends, `.env.example` updated.
8. **Integration test** (`@pytest.mark.integration`) — the hand-labelled set
   through real SPECTER2 + real DeBERTa-MNLI, asserting the same grouping the
   unit tests assert against synthetic vectors.

## Outcome (2026-09-06)

All 8 tasks executed. Two decisions were added during execution and are recorded
in PROGRESS.md alongside D-06-01…D-06-07:

- **D-06-08 — gap vectors are mean-centered before clustering.** Not planned:
  the first real-model integration run failed because raw SPECTER2 `[CLS]`
  vectors are anisotropic (within-theme cosine 0.931 vs 0.871 across — barely
  separable). Centering separates them cleanly (0.354 vs −0.182) and all three
  hand-labelled themes are then recovered exactly. The synthetic unit fixture
  gained a matching shared-cone component so it cannot pass without confronting
  the same geometry.
- **Noise rejection is tested on purpose-built geometry, not the labelled set.**
  Whether HDBSCAN calls a point an outlier is a density judgement, and a
  twelve-statement set has no density to judge; asserting it there would have
  been asserting a small-sample artefact. `test_cluster.py` fixes the label
  array instead and tests only that `-1` never becomes a cluster, which is the
  part this module is responsible for.

Code review found 4 defects, all fixed and covered by tests (see PROGRESS.md):
the missing `app/main.py` table registration, the eagerly-materialized O(n²)
pair list, order-dependent truncation under `CLUSTERING_MAX_STATEMENTS`, and an
unguarded NaN contradiction probability.

Verification: 412 backend tests pass, ruff clean, 5 integration tests pass
against real SPECTER2 + DeBERTa-MNLI, live smoke against Qdrant, and DDL
confirmed on the live Postgres. CLUSTER-01/02/03 marked complete.
