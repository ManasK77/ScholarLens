<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|--------------|
| grobid_client.py -> grobid container | Backend-initiated HTTP call to a self-hosted, trusted service; response content (TEI-XML) is machine-generated, not directly user-supplied |
| tei_parser.py -> XML parsing | Parses GROBID's TEI-XML response; treated as semi-trusted (self-hosted service, but a compromised/malfunctioning container could theoretically return crafted XML) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-04 | Tampering / Information Disclosure | XML External Entity (XXE) injection via a crafted TEI-XML response | mitigate | `xml.etree.ElementTree` does not resolve external entities by default (unlike some `lxml` configurations) — no additional `defusedxml` dependency needed; documented in a code comment in tei_parser.py |
| T-02-05 | Denial of Service | GROBID call hangs on a pathological PDF | mitigate | Bounded `timeout=90.0` on every `httpx.Client` call (D-35); caller (Plan 02-05's service.py) always falls back to PyMuPDF/pdfplumber rather than retrying indefinitely |
| T-02-06 | Tampering | GROBID returns a non-200/malformed response | mitigate | `parse_fulltext`/`parse_header` return `None` on any non-200 status or `httpx.HTTPError`, never raising into the caller — service.py treats `None` as "trigger fallback" |

</threat_model>
