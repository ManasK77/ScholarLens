# Phase 4 Plan — Joint NER + Relation Extraction (Stage 4)

Model choice approved by owner 2026-09-06: **GLiNER2 `JointIE`** (see PROGRESS.md D-04-01).

## Contracts that are fixed (must not change)

`app/ner_re/graph.py` and `tests/ner_re/test_graph.py` already exist and pin:

- `EntityMention(text, entity_type, confidence)` — positional
- `RelationMention(head, relation_type, tail, confidence)` — positional; head/tail
  are **entity text**, not ids (`graph.py` calls `.casefold()` on them directly)
- `JointExtractionResult(entities=[...], relations=[...])`
- `RELATION_ENDPOINTS[relation_type] -> (head_type, tail_type)` — exactly a 2-tuple
  (`graph.py` unpacks it); `RELATION_LABELS` is derived from its keys

## Schema decisions

Entity types (README §15): `model`, `dataset`, `task`, `metric`, `domain`.

Relation endpoints, from README §8 Stage 4's own worked examples:

| relation | head | tail | README example |
|---|---|---|---|
| `trained_on` | model | dataset | `BERT —trained_on→ SQuAD` |
| `evaluated_using` | model | dataset | `GPT-4 —evaluated_using→ GSM8K` |
| `fails_on` | model | domain | `BERT —fails_on→ Low-resource Languages` |
| `achieves` | model | metric | Stage 3 `Contribution → SOTA accuracy` |

`task` is extracted as an entity type and reaches the graph via `Paper-[:MENTIONS]->Entity`,
but no relation in the fixed four-relation set targets it. README's "etc." leaves room to
add task-bearing relations later; the MVP does not invent them.

## Tasks (TDD — test first for each)

1. **`app/ner_re/schema.py`** — the frozen contract above + `ENTITY_TYPES`,
   `RELATION_ENDPOINTS`, dataclass-level validation of unknown types.
2. **`app/ner_re/extractor.py`** — GLiNER2 `JointIE` wrapper.
   - builds the JointIE schema from `ENTITY_TYPES`/`RELATION_ENDPOINTS`
   - **uses `JointIE` only — never the untyped `extract_relations()`**
   - adapts documented `result.to_dict()` output to `JointExtractionResult`
   - resolves relation head/tail **ids -> entity text**
   - drops entities/relations below threshold, of unknown type, or whose
     endpoint types contradict `RELATION_ENDPOINTS` (a mistyped endpoint would
     make `graph.py`'s Cypher MATCH silently write nothing)
   - honours `result.feasible is False` as "constraints unsatisfiable", distinct
     from "nothing found"
   - lazy model load (`lru_cache`), mirroring `get_semantic_classifier`
3. **`app/ner_re/service.py`** — orchestration.
   - `extract_all(session, neo4j, extractor=None, settings=None) -> list[int]`
     (signature must satisfy `routes_backend.py`'s existing 2-arg call)
   - per paper: bounded text built from the abstract + Phase 3 `ExtractedFact`
     sentences; chunked to a char budget; each chunk is **one** joint pass
   - writes via `graph.ensure_graph_schema` + `graph.write_paper_graph`
   - source-agnostic: never branches on `Paper.source`
4. **Settings** — `nerre_*` fields (model name, thresholds, chunk caps) in the
   central config module, all defaulted so existing tests keep passing.
5. **Dependencies** — add `gliner2[local]>=2.0,<3`; regenerate `uv.lock`.
   **Forced consequence:** `gliner2[local]` requires `transformers<5`, but the
   current `sentence-transformers>=6.0` requires `transformers>=5`. Resolution:
   pin `sentence-transformers>=5.1,<6` and `transformers>=4.57,<5`, and make
   `section_classifier.py`'s import tolerate both module layouts.

## Testing strategy

Unit tests use a fake extractor — no model download, consistent with how Phases
2 and 3 test their models. One `@pytest.mark.integration` test exercises the real
checkpoint and stays deselected by default (`addopts = -m "not integration"`).

## Out of scope

Phases 5-10. `routes_backend.router` stays unregistered.
