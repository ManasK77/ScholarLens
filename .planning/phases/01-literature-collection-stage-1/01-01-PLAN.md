<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|--------------|
| corpus.py -> PostgreSQL | Backend-owned credentialed connection; no external/untrusted input reaches SQL directly (all values bound via SQLAlchemy parameterization) |
| corpus.py -> filesystem (`pdf_storage_path`) | `download_pdf` writes bytes fetched from external URLs (arXiv/ACL/Unpaywall, all fixed-domain, not user-supplied) to local disk |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-01 | Tampering | `insert_paper`/`enrich_paper` SQL construction | mitigate | All writes go through SQLAlchemy ORM parameter binding (`Mapped`/`mapped_column`) — no raw string-formatted SQL anywhere in corpus.py |
| T-01-02 | Information Disclosure | `download_pdf` exception path | mitigate | Catches `httpx.HTTPError` and returns `False`; never logs/returns the full response body or internal stack trace to a caller |
| T-01-03 | Denial of Service | `download_pdf` unbounded streamed write | accept | 30s timeout bound (matches Phase 0's `_CHECK_TIMEOUT_SECONDS` precedent scaled for larger payloads); no explicit max-byte cap in this plan since only fixed-domain sources (arXiv/ACL/Unpaywall) call it, not user input — revisit if a future phase pipes user-controlled URLs through this helper |
| T-01-SC | Tampering | pip install (arxiv, bibtexparser, httpx main-dep promotion, respx) | mitigate | Blocking human-verify checkpoint (first task in this plan) confirms each package against pypi.org before install; disposition expected to auto-resolve per standing pre-authorization since all four are pre-audited in 01-RESEARCH.md |

</threat_model>
